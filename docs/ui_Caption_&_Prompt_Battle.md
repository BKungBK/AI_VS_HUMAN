## สีและการจัดหน้า

ใช้โลกเดิมใน `DESIGN.md`/`frame.md`: slate `#0D1117`, panel `#161e2a`, foreground `#F8F9FA`, Human `#FF6B6B`, AI `#748FFC`, mint `#63E6BE` และฟอนต์ IBM Plex Sans Thai จากไฟล์ในเครื่อง สี mint สื่อปุ่มร่วม/ผ่านตรวจ/เสียงที่เลือก สี AI ใช้กับคู่แข่ง AI ในหน้า Host ตรวจเนื้อหาก่อน Start และหน้า Player/Display หลังเปิดเผย ห้ามทำให้สีเป็นวิธีบอกสถานะอย่างเดียว

Player กว้างสูงสุด 540px ในจอใหญ่ และยังอ่านได้ที่ 320/390px ภาพ 4:3 แสดงเต็มภาพโดยไม่ crop โจทย์อยู่ใต้ภาพ ช่องเขียนมี label คงที่และ focus mint ที่เห็นชัด จำนวนตัวอักษรกับสถานะบันทึกอยู่ติดช่องเขียน ปุ่มและทุก action ขั้นต่ำ 48px

Host ใช้ shell เดิมกว้างสูงสุด 1360px คำสั่งหลักกับเวลาอยู่ด้านซ้าย ลิงก์/QR ด้านขวา queue งานเรียงจากเวลาที่รับ แสดงงานรอตรวจครั้งละ 6 ชิ้น เติมงานถัดไปเมื่อผ่าน/ไม่ผ่าน/งดเผยแพร่ เลือกดูทั้งหมดได้ มี 3 คอลัมน์บน desktop, 2 เมื่อจอแคบลง และ 1 บนมือถือ เวลา จำนวนค้างและช่องเหตุผลตรึงระหว่างเลื่อน หลังตัดสินย้าย focus ไปงานรอตรวจถัดไป A/R ทำงานเฉพาะเมื่อ focus อยู่ในพื้นที่ตรวจและเฟสเปิดรับการตรวจ แต่ละชิ้นแสดงชื่อ กลุ่ม revision ข้อความและผลตรวจ ต้องไม่ทำให้ผู้จัดเข้าใจว่าอนุมัติ revision เดิมครอบคลุมข้อความที่แก้ใหม่

Display กว้างสูงสุด 1580px ระหว่างเขียนใช้ภาพใหญ่คู่กับชื่อเฟสและจำนวนข้อความที่รับ ไม่ฉายข้อความรอตรวจ ระหว่าง final vote ใช้ gallery 3 คอลัมน์สูงสุด 7 ผลงานบนจอฉาย รหัสผลงานตรงกับ Player และไม่เผยเจ้าของจน RESULT ผลบนจอ 1920×1080 วาง 7 ผลงานด้านซ้ายและคะแนนกลุ่มทั้ง 6 ด้านขวาให้เห็นครบ ส่วน Player ใช้รายการโหวตแน่นขึ้น ไม่ตัดข้อความ ตรึงเวลาและผลงานที่เลือกเมื่อเลื่อน

## การเขียนและการกู้ข้อมูล

`Intl.Segmenter('th', {granularity:'grapheme'})` นับภาษาไทย สระ/วรรณยุกต์ emoji สีผิวและครอบครัวตามตัวที่เห็น normalize NFC และ trim ก่อนรับใน API ห้ามรับลิงก์ markup หรือ control characters ต้องตรวจเหมือนกันทั้งหน้าเว็บและ API; browser ส่ง `graphemeCount` เองไม่ได้

ร่างใน localStorage ไม่ถือว่าส่งแล้ว หน้าจอแยก “ร่างบนเครื่อง”, “กำลังบันทึก”, “บันทึกร่างในระบบแล้ว” และ “ส่งแล้ว” หลัง refresh ใช้ revision จาก server คืนข้อมูล ถ้าสองแท็บแก้พร้อมกัน revision เก่าถูกปฏิเสธ ผู้เล่นเลือกใช้ข้อความล่าสุดหรือส่งร่างหน้านี้แทนได้อย่างชัดเจน อย่าแก้ให้ auto-overwrite ข้อมูลอีกแท็บ

เมื่อหมดเวลา ใช้เฉพาะข้อความที่ระบบรับสำเร็จล่าสุด อย่าแสดงร่างที่ค้างส่งเป็น accepted submission และอย่าชดเชยเวลารายคน นาฬิกาคำนวณจาก server offset; ทุกอินพุตมี runId/phaseToken และ revision

## ผู้จัดตรวจงาน

ผู้จัดอนุมัติโจทย์และคู่แข่ง AI ก่อน Start ผู้จัดเป็นผู้ตรวจหนึ่งคน ใช้ปุ่ม “ผ่าน / ไม่ผ่าน / งดเผยแพร่” หรือเลือกชิ้นงานแล้วใช้ A/R การไม่ผ่าน/งดเผยแพร่ต้องมีเหตุผล ตรวจร่างได้ระหว่าง WRITING แต่ผู้เล่นแก้แล้วผลตรวจ revision เดิมถูกยกเลิก

หมด 60 วิแล้วงานยังค้างต้องเป็น REVIEW_REQUIRED ไม่เผยงานเพียงเพราะหมดเวลา และไม่ทิ้งกลุ่มท้าย queue การคุม/ตรวจใช้ controller lease เดิม เครื่องสำรองรับช่วงพร้อมเหตุผลและ controllerEpoch ใหม่ได้ expectedReviewVersion ป้องกันผลตรวจซ้อน

## คะแนนและความนิรนาม

Internal เลือกงานเสียงสูงสุด; tie/ไม่มีเสียงใช้ first accepted timestamp แล้ว UUID เป็นลำดับคงที่ กลุ่มไม่มีงานผ่านตรวจไม่มี candidate และได้ 0 แต่ยังโหวตกลุ่มอื่นได้

`support = average(votesFromGroup / frozenRosterCount)` คิดเฉพาะกลุ่มที่มีสมาชิกและมีสิทธิ์โหวตงานนั้น งานคนยกเว้นกลุ่มเจ้าของ งาน AI รวมทุกกลุ่ม `sharedScore = round(1000 × support / bestSupport)` ถ้า best=0 ทุกกลุ่มได้ 0 AI อยู่ใน best แต่ไม่สะสมคะแนน สมาชิกของกลุ่มได้ sharedScore เท่ากัน เก็บตัวเศษ/ตัวหาร support เป็นจำนวนเต็ม PostgreSQL numeric เปรียบเทียบ winner ด้วย cross multiplication และ normalize จากเศษส่วนตรง ๆ; หน้าจอปัดเปอร์เซ็นต์เพื่อแสดงเท่านั้น

ตำแหน่ง candidates สุ่มครั้งเดียวในฐานข้อมูลต่อ run ห้าม shuffle บนทุก snapshot/reconnect และห้ามส่ง groupId/ชื่อผู้สร้างใน finalCandidates ก่อน RESULT `ownGroup` ส่งเฉพาะเพื่อปิดสิทธิ์โหวตของเจ้าของกลุ่ม ผลโหวตไม่อ้างว่าเป็นการทดลอง blind เพราะผู้เล่นอาจจำข้อความกลุ่มตนได้

## Motion และเสียง

ผลเปิดเผยด้วย GSAP timeline ที่ paused และ finite ใช้ transform/opacity กับ stagger สั้น ทุกแถวอ่านได้ตั้งแต่เริ่ม เคารพ `prefers-reduced-motion` ในเกม การเคลื่อนไหวของเว็บสไลด์ยังตามนโยบายเดิมใน frame.md

เกมนี้ใช้เสียงเงียบระหว่างเขียน/ตรวจ/โหวต เพื่อให้ได้ยินผู้จัดและเพื่อน ไม่มี placed music/voice track ที่ต้อง mix จึงไม่เพิ่ม HyperFrames runtime หรือเพลงเพื่อให้เกมทำงาน หากภายหลังเพิ่มเสียง ให้เสียงยืนยันอยู่ต่ำกว่าผู้พูด แยก music/voiceover/sfx และใช้ carve เมื่อมีเพลงใต้ narration ตาม hyperframes-audio
