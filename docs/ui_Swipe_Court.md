# UI — Swipe Court

วันที่ส่งมอบ: 7 ตุลาคม 2026 · `gameId: ai-or-human` · `contentVersion: swipe-court-v1`

คู่มือนี้ใช้ปรับหน้าตา Swipe Court ภายหลัง กติกา เวลา การให้คะแนน สิทธิ์ และเฉลยอ้างอิง [game-build-plan.md](game-build-plan.md) กับ [game-foundation-contract.md](game-foundation-contract.md) ไฟล์คู่มือนี้ไม่ใช่คำสั่งให้เปลี่ยนกติกาเหล่านั้น

## ทางเข้าของผู้เล่นและไฟล์หลัก

| หน้าจอ | ทางเข้าหรือสถานะ | จุดประสงค์ |
|---|---|---|
| ผู้เล่น | `/play/:roomCode` เมื่อคิว `03.05` | โหลดภาพ เลือก Human/AI ด้วยปุ่มหรือการปัด ติดตามรอบ และเทียบคำตอบหลังเริ่มเฉลย |
| ผู้จัด | `/presenter/:roomCode` เมื่อคิว `03.05` | ตรวจความพร้อม เริ่ม/พัก/เล่นต่อ ดูคำตอบรวม ยืนยันผล และเปลี่ยนคิว |
| จอฉาย | `/display/:roomCode` เมื่อคิว `03.05` | แสดงภาพรอบเดียวกับผู้เล่น จากนั้นนำเสนอที่มาและสถิติทีละภาพ |
| เข้าร่วม | `/play/:roomCode` ก่อนเข้าห้อง | ชื่อเล่นและกลุ่มตามระบบห้องเดิม |

- `src/game-client/GameApp.tsx`: `SwipePlayer`, `SwipeHost`, `SwipeDisplay`, ตัวช่วย preload, ปุ่ม Human/AI และลำดับเฉลย
- `src/game-client/game.css`: เลย์เอาต์ สีของตัวเลือก การตอบสนองต่อ swipe การจัดกริดเฉลย และ responsive
- `src/game-client/network.ts`: session, polling, clock offset, error และ retry เดิม
- `src/shared/game-contracts.ts`: เฉพาะข้อมูลภาพที่ปลอดภัยก่อนเฉลย; ผลรายภาพและเครดิตมีเฉพาะเมื่อเริ่ม `REVEAL_ALL`
- `api/games/swipe-court-content.ts`: manifest ฝั่งเซิร์ฟเวอร์ที่ผูกไฟล์ ผู้สร้าง ที่มา ใบอนุญาต classification และ brief การสร้างภาพกับ content version
- `db/schema.sql`: ตารางภาพ ลำดับรอบ คำตอบแรก การล็อกเวลา digest คะแนน และนโยบายการเปิดเฉลย
- ภาพที่ผู้เล่นดาวน์โหลด: `public/assets/swipe-court/sc-*.jpg` ชื่อไฟล์ไม่บอกประเภท

## ภาษาภาพและการจัดวาง

คงพื้น slate เข้มและ IBM Plex Sans Thai ของเกมหลัก Human ใช้ coral และ AI ใช้ periwinkle; ปุ่มคำตอบแสดงชื่อและทิศทางเสมอ ภาพเป็นจุดสนใจหนึ่งเดียว ล้อมด้วยรางคำตอบซ้าย/ขวาและเวลารอบ ไม่มีคำตอบถูก/ผิดระหว่างเล่น

หน้า Player วางหัวเกม/เวลาและกติกาคงที่ไว้เหนือภาพ 4:3 ขนาดใหญ่ ซ้ายคือ “มนุษย์” ขวาคือ “AI” ใต้ภาพมีปุ่มขนาดกดง่ายสองปุ่มเพื่อใช้แทนการปัด หน้า Host วางตัวควบคุมไว้ข้างลิงก์/QR สำหรับผู้เล่น จอฉายเน้นภาพและจำนวนผู้ตอบ ช่วงเฉลยเปลี่ยนจากภาพเดี่ยวทุก 3 วินาทีเป็นกริดทั้ง 8 ภาพใน 6 วินาทีสุดท้าย ผู้เล่นเห็นกริดคำตอบของตนในช่วงเดียวกัน พร้อมสถิติและคำตอบส่วนตัว; รายละเอียดเครดิต/สิทธิ์เปิดดูได้แยกต่อภาพ

โครงหน้า Player กว้างสูงสุดประมาณ 1,120px และจอฉาย 1,580px ที่ 800px ป้ายรางและปุ่มลดขนาด; ที่ 560px เนื้อหาเรียงเป็นคอลัมน์ การ์ดภาพยึดสัดส่วน 4:3 เพื่อให้วัตถุไม่โดนครอป จุดตรวจภาพควรมีมือถือ 390×844, Host 1366×900 และจอฉาย 1920×1080

## พฤติกรรมที่ UI ต้องรักษา

| สถานะ | สิ่งที่ต้องคงไว้ |
|---|---|
| GAME_READY | โหลดและ decode ภาพครบทั้ง 8 ก่อนส่ง readiness; Host ยังเริ่มได้เมื่อมีคนโหลดไม่ครบ แต่เครื่องนั้นปิดการตอบจนภาพปัจจุบันแสดงได้ |
| COUNTDOWN | นับ 3 วินาทีจาก server และยังตอบไม่ได้ |
| ANSWERING | 8 รอบ รอบละ 4 วินาที; แสดงภาพที่ทุกเครื่องตรงกัน จำนวนคำตอบ และ timer จาก server |
| การเลือก | ปัดซ้าย = Human, ขวา = AI; เกณฑ์ปัดคือ 20% ของความกว้างการ์ด โดย clamp 48–96 CSS px; ปุ่มสองข้างส่งคำสั่งเดียวกัน |
| คำตอบรับแล้ว | คำตอบแรกของผู้เล่นต่อภาพถูกล็อกทันที ไม่มีคะแนน/เฉลยรายภาพจนถึง `REVEAL_ALL`; การ์ดเคลื่อนออกตามทิศหลัง server รับคำตอบ |
| REVEAL_ALL | เปิดที่มา ครีเอเตอร์ ใบอนุญาต prompt brief จำนวน Human/AI จำนวนไม่ตอบ และจำนวนถูก; จอฉายเฉลยทีละภาพ 3 วินาที และทั้ง Player/Display แสดงกริด 8 ภาพช่วง 6 วินาทีท้าย โดยผู้เล่นยังเห็นคำตอบรายภาพของตน |
| สรุป | 24 วินาทีแรกใช้ไล่ภาพ; 6 วินาทีสุดท้ายแสดงทั้ง 8 ภาพ ตารางคะแนนเฉลี่ยกลุ่ม และความแม่นยำรวม |
| COMPLETED | ผู้จัดกดยืนยันด้วยตนเองหลังครบช่วงเฉลย แล้วไปคิว 03.03; ไม่มี auto-finish |
| CANCELLED | แสดงว่ายกเลิกและไม่นับคะแนน ไม่แทนผลที่ยังไม่จบด้วยศูนย์ |
| เครือข่ายขาด/ภาพยังโหลด | คงสถานะล่าสุด ปิดการตอบเมื่อ snapshot เก่าหรือภาพยังไม่พร้อม และไม่เพิ่มเวลาส่วนบุคคล |

คะแนนถูกภาพละ 100 สูงสุดรายคน 800 ไม่มีโบนัสความเร็ว คะแนนกลุ่มเป็นคะแนนถูกรวม ÷ จำนวนสมาชิก roster ณ Start รวมคนที่ไม่ตอบ ค่าเปอร์เซ็นต์ภาพคำนวณจาก accepted answers เท่านั้น หากไม่มีผู้ตอบต้องแสดง “ไม่มีคำตอบ” หรือ “—” ห้ามหารด้วยศูนย์

## ปรับแต่งได้โดยไม่เปลี่ยนสัญญา

- ระยะห่าง ขนาดภาพ สี และ breakpoint ปรับในคลาส `.swipe-*` ของ `src/game-client/game.css`; อย่าลดพื้นที่ปุ่มหรือ focus ring ที่เห็นชัด
- ภาษา คำอธิบายภาพ และเครดิตปรับใน `src/game-client/GameApp.tsx` และ manifest โดยถ้าเปลี่ยนชุดภาพ/ลำดับเฉลย/คำตอบ ให้เพิ่ม `contentVersion` ใหม่ ไม่แก้ record เดิมทับ run ที่บันทึกไว้
- การออกจากการ์ดหลังรับคำตอบเคารพ `prefers-reduced-motion`; ไม่ต้องมีเสียงหรือเพลงเพื่อให้ตอบได้
- ตรวจ build และ API contract ด้วย `npm run game:build` และ `npm run game:test`; ทดสอบหน้าจอครบด้วย `npm run game:qa2`

## ที่มาภาพและการบันทึก brief

Human ใช้ภาพเปิดสิทธิ์: Allan's Island Lighthouse โดย MMMcMaster (CC0) และภาพ Public Domain/Open Access จาก The Met — Roger Fenton, object 283087; Paul Cézanne, object 435883; Henry Fuseli, *The Nightmare* (Public Domain) ลิงก์และข้อความเครดิตรายภาพอยู่ใน manifest และเปิดให้เห็นในช่วงเฉลย

ภาพ AI ทั้งสี่ใบสร้างสำหรับเกมโดยไม่มีภาพอ้างอิงภายนอก brief ที่เก็บไว้กับแต่ละภาพสรุปจากบันทึกช่วงสร้างเพื่อให้แก้/สร้างเนื้อหาต่อได้: ภาพประภาคาร, ภาพจัดวางผลไม้, ภาพวาดหุ่นนิ่งแอปเปิล/ลูกแพร์ และภาพอาหารเช้าทั่วไป brief เหล่านี้ติดป้ายว่าเป็น brief ไม่ใช่ prompt ฉบับคำต่อคำ
