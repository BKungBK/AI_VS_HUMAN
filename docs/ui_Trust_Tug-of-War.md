# UI — Trust Tug-of-War

วันที่ส่งมอบ: 6 ตุลาคม 2026 · รุ่น `trust-tug-v1`

ไฟล์นี้เป็นคู่มือปรับ UI เกมแรก ไม่ใช่คำสั่งให้แก้กติกา คะแนน หรือเกมอื่นทันที

## จุดเข้าและไฟล์ที่เกี่ยวข้อง

| หน้าจอ | URL | หน้าที่ |
|---|---|---|
| ทางเข้า | `/games` | กรอกรหัสห้อง / ผู้จัดเข้าสู่ระบบ / สร้างห้อง / กลับห้องเดิม |
| ผู้เล่น | `/play/:roomCode` | ชื่อเล่น กลุ่ม เลือกฝั่ง ทดลอง แตะจริง ผลส่วนตัว |
| ผู้จัด | `/presenter/:roomCode` | QR ความพร้อม ทดลอง Start Pause Resume ผล จบเกม/ไปต่อ |
| จอฉาย | `/display/:roomCode` | เชือก แรงเฉลี่ย สมาชิก คะแนนกลุ่ม และสไลด์ตามคิวห้อง |

- `src/game-client/GameApp.tsx`: Home, Join, Player, Host, Display, Arena, Scores, Header และ Time
- `src/game-client/game.css`: สี เลย์เอาต์ ขนาดปุ่ม ฟอนต์ จุดเปลี่ยน responsive และ reduced motion
- `src/game-client/network.ts`: session, clock offset, snapshots, retry, Realtime และข้อความสถานะ
- `src/shared/game-contracts.ts`: types ที่ส่งถึง frontend ไม่มี scorer หรือ secret
- `api/app.ts`, `api/validation.ts`: API และสิทธิ์ ไม่ควรแก้เพื่อเปลี่ยนหน้าตา
- `db/schema.sql`: เวลากลาง คะแนน roster และ transaction ไม่ควรเปลี่ยนด้วยงานตกแต่ง UI

## ภาษาภาพ

รักษาอัตลักษณ์เว็บสไลด์เดิม: พื้นเข้มสำหรับห้องฉาย ฟอนต์ IBM Plex Sans Thai ที่เก็บในเครื่อง Human ใช้สี coral, AI ใช้ periwinkle และปุ่มหลักใช้ mint เชือกเป็นแผนภาพเรขาคณิตที่อธิบายแรงเฉลี่ย ไม่มีภาพถ่ายหรือภาพจำลองประกอบเกม

| `--game-panel` | `#161e2a` | พื้นส่วนรอ/ข้อมูล |
| `--game-line` | `#364255` | เส้นแบ่งข้อมูล |

## รูปแบบแต่ละจอ

**Player:** พื้นที่กว้างสูงสุด 540px ขอบข้าง 24px บนมือถือ แสดงชื่อและกลุ่มด้านบน ปุ่ม Human/AI วางสองฝั่งเสมอ เมื่อเล่นให้มี timer ปุ่มดึง และจำนวนที่ระบบรับแล้วเป็นลำดับหลัก ข้อความส่งไม่สำเร็จไม่ทับปุ่ม

**Host:** กว้างสูงสุด 1360px ใช้เนื้อหาควบคุมเกมด้านซ้ายและ QR ด้านขวา รายชื่อกลุ่มแยกอยู่ด้านล่าง งานอันตรายต่อรอบ เช่น Cancel/Replay อยู่ในรายละเอียดที่เปิดเอง ปุ่มจบเกมมีเพียงปุ่มเดียว หน้านี้เป็นชุดควบคุมขั้นต่ำตามแผน ยังไม่ได้ทำ layout Host ฉบับสุดท้าย

**Display:** พื้นที่กว้างสูงสุด 1480px เชือกและชื่อฝั่งเป็นภาพหลัก QR ใช้เฉพาะก่อนล็อกทีม คะแนนแสดงชื่อกลุ่ม คะแนนเฉลี่ยและจำนวนสมาชิกใน roster จอไม่แสดงอันดับรายบุคคล เมื่อผู้จัดจบเกมไปคิว 03.01 จะเปิดสไลด์เดิมใน iframe ที่ใช้คิวห้อง

Responsive ที่ 900px: รายชื่อกลุ่มเปลี่ยนจาก 3 เป็น 2 คอลัมน์ ที่ 640px: Home และ Host เปลี่ยนเป็นคอลัมน์เดียว และรายชื่อกลุ่มเหลือ 1 คอลัมน์; Display ขนาดโทรศัพท์ลดขนาดเชือกและใช้ตารางคะแนนหนึ่งคอลัมน์ จุดตรวจภาพ 1366×900, 390×844 และ 1920×1080

## สถานะที่ต้องคงไว้เมื่อปรับ UI

| สถานะ | สิ่งที่ผู้เล่นต้องเห็น/ทำได้ |
|---|---|
| Join | กรอกชื่อ 1–24 ตัวอักษร เลือกกลุ่มเอง เห็นจำนวนสมาชิกแต่ละกลุ่ม |
| GAME_READY | เลือก/แก้ฝั่ง โหลดฟอนต์แล้วส่งความพร้อม รอผู้จัดเริ่ม |
| Practice | ทดลอง 15 วินาที ใช้ counter ในหน้าต่าง ไม่คิดคะแนน |
| COUNTDOWN | 3 วินาที ฝั่งถูกล็อก ปุ่มดึงยังใช้งานไม่ได้ |
| PULLING | 10 วินาที pointerdown หนึ่งครั้งต่อหนึ่งแตะ เห็นจำนวนรับแล้วและจำนวนรอส่ง |
| Pause | timer หยุด ปุ่มดึงปิด จำนวนแตะเดิมคงอยู่ |
| อีกแท็บเล่นอยู่ | อ่านผลได้ ปุ่มดึงปิด ใช้ “เล่นต่อที่แท็บนี้” เพื่อรับสิทธิ์เอง |
| ผู้มาช้า / ไม่เลือกฝั่ง | อธิบายเหตุผลที่เล่นรอบนี้ไม่ได้ รอรอบถัดไป |
| RESULT | คะแนนตนเองและกลุ่มรอยืนยัน ผล Human/AI ไม่ให้โบนัส ค้างรอผู้จัด |
| COMPLETED | ยืนยันคะแนนแล้ว Player รอเกมถัดไป Display ไปคิวถัดไป |
| CANCELLED | “ยกเลิก / ไม่นับคะแนน” แยกจากคะแนน 0 |
| API ขาดการเชื่อมต่อ | คงภาพที่ระบบยืนยันล่าสุด แสดงข้อความและปิดการแตะ |

## กติกาที่ UI ต้องไม่เปลี่ยน

- เลือก Human/AI ไม่ใช่เปลี่ยนกลุ่ม 1–6 และเปลี่ยนฝั่งหลัง Start ไม่ได้
- แตะที่ระบบรับสำเร็จ 1 ครั้ง = 10 คะแนน และแตะได้ไม่จำกัดตลอดช่วงดึง 10 วินาที ไม่มีเพดาน 50 แตะหรือ 500 คะแนน
- หลังหมดเวลา คะแนนกลุ่มคำนวณจากคะแนนแตะที่รับจริงรวมกัน แล้วหารด้วยจำนวนสมาชิกใน roster ที่ถูกล็อกตอนเริ่มเกม รวมสมาชิกที่ไม่ได้แตะ
- คำว่า “ไม่จำกัด” เป็นกติกาของเกม; ระบบยังส่งแตะเป็นชุดและนับเฉพาะ event ที่ฐานข้อมูลตอบรับสำเร็จ เพื่อให้ผลตรวจสอบย้อนหลังได้
- จำนวนชั่วคราวต้องไม่แสดงเป็นคะแนนที่ยืนยันแล้ว เครือข่ายส่งช้าหลัง deadline ไม่รับคะแนนย้อนหลัง
- คะแนนกลุ่มใช้ roster ตอน Start คนไม่แตะเป็น 0 คนหลุดไม่ลดตัวหาร
- ผลแรงเฉลี่ยคำนวณจำนวนแตะ/จำนวนคนของแต่ละฝั่ง ฝั่งว่างให้ “ไม่มีคู่เปรียบเทียบ”
- QR ซ่อนเมื่อ Start ล็อกทีม ผลค้างจนกด “จบเกม / ไปต่อ” ไม่เลื่อนคิวเอง
- Keyboard Enter/Space ต้องไม่นับรัวจาก repeat และต้องไม่กระตุ้น pointer+click ซ้ำ
- สีต้องมีข้อความกำกับ มี focus ที่เห็นได้ และเคารพ prefers-reduced-motion

## วิธีตรวจหลังปรับแก้

```powershell
npm run game:build
npm run game:test
npm run game:start
# อีก terminal
npm run game:qa
```

ตรวจ screenshot ใน `qa/game1/` โดยเปิดภาพจริง โดยเฉพาะ join, ready, pulling, offline, result และ Display อย่าใช้ผล TypeScript อย่างเดียวรับรองหน้าตา คำถามชวนคุยหลังเกม: “คุณเลือกเพราะประสบการณ์ หลักฐาน หรือความคุ้นเคย แล้วจะไว้ใจฝั่งเดิมในงานศิลปะด้วยไหม?”
