# ทดสอบ Trust Tug-of-War

## เปิดครั้งแรก

1. ดับเบิลคลิก `Start-Game.cmd` ที่รากโปรเจกต์ โปรแกรมติดตั้ง dependencies ถ้าจำเป็น ตรวจ build และเปิด server
2. เปิด `http://localhost:5180/games` บนเครื่องนี้ รหัสผู้จัดดูจากหน้าต่าง launcher หรือ `data/host-key.txt`
3. เข้าสู่ระบบผู้จัด กด “สร้างห้องทดสอบ” ได้ห้องสำหรับ 32 คน 6 กลุ่ม
4. เปิด “จอฉาย” ในอีกหน้าต่าง จออยู่ที่ `/display/รหัสห้อง`
5. เปิดลิงก์ `/play/รหัสห้อง` ใน browser อีก profile หรือมือถือ กรอกชื่อเล่น เลือกกลุ่ม และฝั่ง Human/AI
6. ทดลอง 15 วินาที หรือกดเริ่มโดยตรง เมื่อ countdown 3 วินาทีจบ ให้แตะดึง 10 วินาที แตะได้ไม่จำกัด ระบบจะนับเฉพาะแตะที่รับสำเร็จและให้ 10 คะแนนต่อครั้ง
7. ตรวจผล ผู้จัดกด “จบเกม / ไปต่อ” ระบบยืนยันคะแนนและจอฉายไปสไลด์ 03.01

## มือถือบน Wi-Fi เดียวกัน

server ฟัง port 5180 ทุก interface เครื่องนี้ IP ณ ตอนตรวจคือ `192.168.1.143` เปิด `http://192.168.1.143:5180/games` จากหน้าผู้จัดก่อนสร้าง/เปิดห้อง QR จะใช้ origin นี้ มือถือเปิดลิงก์บน IP เดียวกัน ห้ามใช้ QR ที่ชี้ localhost จากอีกเครื่อง

IP เปลี่ยนได้ ให้ดู LAN URL ที่ server พิมพ์เมื่อเริ่ม ถ้า Windows ถามอนุญาต Node ให้เข้าถึงเครือข่ายส่วนตัว ให้ใช้เครือข่ายที่กำลังทดสอบ เครื่องและมือถือยังต้องเข้าถึงกันได้บน Wi-Fi นั้น

## สิ่งที่ควรลอง

- สองคนเลือกคนละฝั่ง/คนละกลุ่ม แล้วแตะจำนวนต่างกัน ตรวจคะแนนกลุ่มตามสมาชิก
- แตะให้เกิน 50 ครั้งในรอบเดียว ตรวจว่าปุ่มยังใช้งานและคะแนนไม่ถูกตัด แล้วผลกลุ่มยังหารด้วยสมาชิกใน roster ตอนเริ่ม
- เลือกฝั่งเดียวทั้งห้อง และไม่มีใครเลือกฝั่ง ตรวจว่าไม่สร้างผลผู้ชนะจากข้อมูลว่าง
- รีเฟรชระหว่างเล่น ได้ชื่อ ฝั่ง จำนวนแตะและเวลาที่เหลือเดิม
- ผู้จัด Pause/Resume เวลาและจำนวนแตะเดิมคงอยู่
- เปิดผู้เล่นอีกแท็บ ใช้ “เล่นต่อที่แท็บนี้” แท็บเก่าจะอ่านได้แต่เล่นไม่ได้
- เปิดลิงก์ Host อีกแท็บ ใช้รหัสผู้จัดเดียวกัน แล้วรับช่วงควบคุมพร้อมเหตุผล
- เข้าหลัง Start ผู้เล่นรอรอบถัดไป ยังเข้ากลุ่มได้แต่ไม่เพิ่ม roster ย้อนหลัง
- อยู่หน้า RESULT ไว้นาน เกมจะไม่จบเอง
- หลังยืนยัน ใช้เล่นใหม่พร้อมเหตุผล คะแนนเดิมจะออกจากคะแนนที่นับ มีประวัติรอบเดิม
- ดาวน์โหลดผล JSON จาก “จัดการรอบและเปลี่ยนคิว” เปรียบเทียบคะแนนกับ roster

## ข้อมูลและคำสั่ง

ข้อมูล PostgreSQL อยู่ใน `data/pg` session identity อยู่ใน HttpOnly cookie ของ browser รหัสผู้จัดอยู่ใน `data/host-key.txt` อย่าลบข้อมูลเหล่านี้ระหว่างซ้อมหากต้องการกลับห้องเดิม Stop server ด้วย Ctrl+C เมื่อเปิดจาก launcher เริ่มอีกครั้งจะกู้ห้อง/รอบ/คะแนน ไม่สร้างเกมซ้ำ

```powershell
npm run game:build
npm run game:test
npm run game:start
# อีก terminal เมื่อ server เปิดอยู่แล้ว
npm run game:qa
node scripts/game-load-check.mjs
# หรือ
npm run game:load
```

## ขอบเขตชุดนี้

ชุดนี้เล่นทดสอบในเครื่องและ LAN ได้ ใช้ Elysia บน Node และ PGlite (PostgreSQL ฝังใน backend พร้อมบันทึกลง disk) ใช้ HTTP snapshots และ SSE สำหรับ Realtime ข้อมูลทั้งหมดผ่าน transaction และเวลา DB ไม่มีฐานข้อมูลใน browser

ยังไม่ได้ deploy Vercel/Supabase ของเกมนี้ Local Host ใช้รหัสเครื่อง ไม่ใช่บัญชี Supabase และ SSE ไม่ใช่ Supabase Realtime ไฟล์ `db/schema.sql` ใช้ PostgreSQL และ backend ต่อฐาน dedicated PostgreSQL ได้ผ่าน `GAME_DATABASE_URL` แต่การเปลี่ยนเป็นระบบงานจริงต้องทำ Supabase Auth/role mapping, grants/RLS, Realtime authorization, HTTPS และ staging load ตามแผนก่อน ไม่ใช้ Supabase โปรเจกต์อื่นแทนฐานเกม

ผลทดสอบใน `qa/game1/` เป็นผลเฉพาะเครื่องนี้ ไม่รับรอง iPhone Safari/Android จริง เครือข่ายงานจริง หรือการซ้อมงาน 50 นาที เกม 2–7 ยังไม่ได้สร้างในงานนี้
